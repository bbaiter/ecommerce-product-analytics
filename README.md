

# E-commerce Product Analytics

Проект посвящен полному циклу обработки и анализа сырых логов e-commerce (20.6 млн событий за 5 месяцев). Включает проектирование схемы базы данных, написание ETL-скриптов на Python, разведочный анализ данных (EDA) в Jupyter Notebook и автоматизированный расчет ключевых продуктовых метрик с помощью SQL.

## TL;DR (Ключевые результаты)
*   **Выручка:** $6.35M за период, средний чек (AOV) — $40.79.
*   **Главная проблема:** 87.19% брошенных корзин. Пользователи активно добавляют товары, но не доводят до оплаты.
*   **Воронка:** Конверсия в покупку низкая (6%). Только 22% пользователей возвращаются на сайт в день, отличный от первого визита.
*   **Время до покупки:** Медиана времени покупки после первого просмотра **8.2 часа**, в то время как среднее -- **11.9 дней**. Это говорит об импульсивных покупках и длинном хвосте.

### Описание директорий

*   **`bd_structure/`** — содержит визуализации структуры базы данных: концептуальную (`concept_map.png`), логическую (`logical_map.png`) и физическую (`physical_sceme.png`) схемы.
*   **`data/`** — директория для хранения исходных данных (`.csv`) и файла базы данных SQLite (`ecommerce.db`). 
    *   *Данные взяты с Kaggle: [E-commerce Behavior Data](https://www.kaggle.com/datasets/mkechinov/ecommerce-events-history-in-cosmetics-shop).* 
    *   Перед запуском скриптов скачайте данные и поместите их в эту папку.
*   **`notebooks/`** — содержит `Product_analytics.ipynb` с разведочным анализом данных (EDA). Анализ выполнен на примере одного месяца для выявления паттернов поведения пользователей.
*   **`scripts/`** — Python-скрипты для автоматизации работы с базой данных.
*   **`sql/`** — SQL-скрипты для расчета основных метрик.

## Основные выводы и инсайты

**1. Выручка и лидеры рынка**
*   Пик выручки пришелся на ноябрь 2019 ($1.53M), в декабре наблюдается просадка до $1.07M. 
*   Топ-5 брендов по выручке: *runail, grattol, irisk, uno, strong*.
*   Распределение выручки на пользователя имеет лог-нормальное распределение (большинство чеков маленькие, но есть длинный хвост крупных трат).

**2. Воронка и удержание**
*   **Конверсия (CR):** 6.0% (110 518 покупателей из 1.63 млн уникальных пользователей).
*   **Stickiness (DAU/MAU):** Держится на уровне 4.5% — 5.0%, что говорит о низкой ежедневной привычке возвращаться на сайт.
*   **Время до покупки:** медиана — **8.2 часа**, среднее — **11.9 дней**. Большинство покупателей оформляют заказ в день первого визита.

**3. Поведенческие паттерны (из EDA)**
*   **Дни недели:** Пик активности приходится на четверг. В выходные фиксируется неожиданный спад посещаемости и покупок.
*   **Время суток:** Трафик растет днем (пики в 10:00 и 20:00). Покупки совершаются в обед (около 12:00) и вечером (около 18:00).

## Установка и запуск

1.  **Клонируйте репозиторий и перейдите в папку проекта:**
    ```bash
    git clone <url_репозитория>
    cd Eda_analysis_proj
    ```

2.  **Создайте и активируйте виртуальное окружение:**
    ```bash
    python3 -m venv venv

    ```

3.  **Установите зависимости:**
    ```bash
    pip install -r requirements.txt
    ```

4.  **Подготовьте базу данных:**
    Убедитесь, что CSV-файлы лежат в папке `data/`. Затем выполните скрипты инициализации и загрузки данных:
    ```bash
    cd scripts
    python3 init_db.py
    python3 insert.py
    ```

## Использование

### Запуск отдельного SQL-запроса
Скрипт `select.py` принимает в качестве аргумента имя SQL-файла. Он находит файл в папке `sql/`, выполняет его и возвращает DataFrame.
```bash
python3 select.py average_DAU.sql
```

### Запуск всех метрик сразу (Отчет)
Скрипт `run_all.py` автоматически находит все `.sql` файлы в папке `sql/`, выполняет их по очереди и выводит результаты в консоль. Это позволяет быстро получить сводный отчет по всем показателям.
```bash
python3 run_all.py
```

### Доступные SQL-метрики
В папке `sql/` находятся скрипты для расчета следующих показателей:
*   `revenue_aov_total.sql` — общая выручка, количество заказов и средний чек (AOV).
*   `revenue_aov_months.sql` — выручка и AOV в разрезе по месяцам.
*   `average_DAU.sql` — среднее количество уникальных активных пользователей в день (DAU) по месяцам.
*   `stickness.sql` — метрика вовлеченности (Stickiness = DAU / MAU).
*   `conversion_rate.sql` — конверсия из просмотра в покупку.
*   `abandonned_carts.sql` — доля брошенных корзин.
*   `average_buytime.sql` — среднее время от первого визита до покупки.
*   `brannds_revenue.sql` — топ-10 брендов по выручке и уникальным покупателям.

## Ограничения (Limitations)
*   **Исторические данные:** Используется статичный датасет.
*   **EDA на примере:** Ноутбук анализирует один месяц (ноябрь), в то время как SQL-скрипты охватывают весь период (5 месяцев).
